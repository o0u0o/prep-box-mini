# 数据存储设计方案

> 版本：v1.0 | 日期：2026-05-09 | 作者：面试准备盒 / PrepBox 团队

## 1. 背景

当前阶段后端 API 尚未就绪，但前端页面开发和产品验证需要持续推进。需要一套低成本的本地数据方案，同时不影响后续无缝切换到远程 API。

## 2. 方案选型

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| **JavaScript 数据模块** | 小程序构建器兼容性好；可通过 `require()` 读取；与 API 返回结构一致；git diff 友好 | 数据量大时包体积增大 | **采用** |
| CSV 文件 | Excel 编辑友好 | 小程序无内置解析器，需引三方库；全是字符串，需手动转类型；与 API 格式不一致 | 不采用 |
| wx.setStorage | 原生 KV 存储 | 不适合结构化列表查询；数据不进版本控制；用户清缓存即丢失 | 不采用 |
| 云开发数据库 | 免服务器 | 有额外成本；依赖微信云环境；数据结构受限 | 可选（后期） |

## 3. 目录结构

```
prep-box-mini/
├── data/                          ← 本地数据源（.js 模块）
│   ├── companies.js               ← 公司/机构列表

│

```

## 4. 核心架构：数据源适配器模式

### 4.1 数据流

```
┌──────────┐      ┌──────────────┐      ┌────────────────────┐
│  页面层    │ ──▶ │  Model 层     │ ──▶ │  DataSource 适配器  │
│ (home.js) │      │ (company.js) │      │                    │
└──────────┘      └──────────────┘      │  useLocalData?     │
                                         │  ┌───────────────┐ │
                                         │  │ true:          │ │
                                         │  │ require(.js)   │ │
                                         │  ├───────────────┤ │
                                         │  │ false:         │ │
                                         │  │ Http.request() │ │
                                         │  └───────────────┘ │
                                         └────────────────────┘
```

### 4.2 设计原则

1. **页面层**只调用 Model 层，不关心数据来源
2. **Model 层**只调用 DataSource 适配器，不直接 require 数据模块，也不直接调用 Http
3. **DataSource** 根据 `config.useLocalData` 分发到本地数据模块或远程 API
4. 切换数据源**只改 config 开关一处**，页面和 Model 代码零改动

### 4.3 关键代码示例

**config/config.js**
```javascript
const config = {
  apiBaseUrl: 'https://your-backend.example.com',
  useLocalData: true // true → 本地数据模块 / false → 远程 API
};
```

**model/datasource.js**（简化示例）
```javascript
import { config } from '../config/config';
import { Http } from '../utils/http';

const { companys: localCompanies } = require('../data/companies.js');

class DataSource {
  static async searchCompanies(keyword) {
    if (config.useLocalData) {
      const filtered = localCompanies.filter(company =>
        company.name.includes(keyword) || company.type.includes(keyword)
      );
      // companys 为后端历史响应字段，暂时保留以兼容调用方。
      return { companys: filtered };
    }
    return Http.request({
      url: '/app/company/list/like',
      data: { keyword }
    });
  }
}
```

**model/company.js**（调用方）
```javascript
import { DataSource } from './datasource';

class Company {
  static async searchByKeyword(keyword) {
    return DataSource.searchCompanies(keyword);
  }
}
```

## 5. 数据格式约定

### 5.1 companies.js

```javascript
module.exports = {
  companys: [
    {
      id: 101,
      name: '示例科技（深圳）有限公司',
      uscc: '统一社会信用代码',
      legal_rep_name: '法定代表人姓名',
      province: '广东省',
      city: '深圳市',
      district: '南山区',
      address: '科技园 XX 路 1 号',
      source: '公开来源或案号',
      type: '劳动争议'
    }
  ]
};
```

字段说明：
- `id`：唯一标识，后端就绪后由数据库自增生成
- `uscc`：统一社会信用代码；无法核实时保留空字符串
- `legal_rep_name`：法定代表人姓名；无法核实时保留空字符串
- `source`：信息来源/可核验依据
- `type`：分类，与 `categories.js` 对应

### 5.2 categories.js

```javascript
module.exports = [
  { value: '劳动争议', label: '劳动争议' },
  { value: '行政处罚', label: '行政处罚' }
];
```

## 6. 迁移路径

### 阶段一（当前）：纯本地

```
config.useLocalData = true
```

所有数据从 `/data/*.js` 模块读取，无后端依赖。

### 阶段二：逐接口迁移

后端就绪后，可按接口粒度逐步切换。在 `datasource.js` 中按方法级别控制：

```javascript
static async searchCompanies(keyword) {
  if (config.useLocalData) { ... }
  return Http.request({ ... });
}
```

### 阶段三：全量 API

```
config.useLocalData = false
```

一行改动完成切换。本地数据模块可保留作为开发数据或离线兜底。

## 7. 新增数据操作指南

### 添加公司/机构数据

1. 打开 `data/companies.js`
2. 在 `companys` 数组中追加一条，`id` 取当前最大值 +1
3. 必填字段：`id`、`name`、`uscc`、`legal_rep_name`、`province`、`city`、`type`、`source`
4. 保存后刷新小程序即可看到

### 添加新数据实体

1. 在 `data/` 下新建 `xxx.js`，通过 `module.exports` 导出数据
2. 在 `model/datasource.js` 中 require 并添加对应方法
3. 在 `model/` 下新建或复用已有 Model 调用 DataSource
4. 页面只调用 Model，不直接引用数据模块

## 8. 注意事项

1. **包体积**：本地数据会打入小程序包。数据量大时（>500 条）建议压缩或分片加载
2. **数据一致性**：本地模块的字段结构必须与后端 API 返回格式保持一致
3. **敏感信息**：不要在数据模块中存放非必要个人信息、证据原件、联系方式
4. **版本控制**：`data/*.js` 纳入 git 管理，每次数据变更都有记录
